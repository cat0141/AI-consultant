# AI增长操作系统领导汇报稿

> 汇报用途：面向管理层说明 AI 增长操作系统的产品方向、资料依据、设计原则、阶段路径、资源支撑和近期推进计划。  
> 建议汇报时长：20-30分钟。  
> 当前版本：用于内部讨论，不作为最终 PRD。  

---

## 1. 一句话结论

AI增长操作系统要做成一套面向代账公司顾问和经营管理者的增长工作台：

> 基于云帐房已有客户数据、票财税数据、服务过程数据、云微/企微沟通数据和外部企业信息，通过“数据标签 + 规则引擎 + AI生成规则配置表 + 小样本验证 + 批量分析 + 行动建议清单 + 顾问反馈”，帮助代账公司从存量客户中发现可跟进的增长机会，并持续沉淀企业内部规则和行业通用规则。

核心链路：

```text
数据源
  -> 字段标签
  -> AI生成规则配置表
  -> 用户手动修改规则
  -> 少量企业样本验证
  -> 保存为企业内部规则
  -> 批量分析客户
  -> 输出推荐名单和AI分析结果
  -> 推送顾问行动建议清单
  -> 记录顾问反馈
  -> 沉淀通用规则和私有规则
```

---

## 2. 为什么要做 AI 增长操作系统

AI服务顾问效率线解决的是顾问重复劳动问题，例如客户问答、催资料、税金说明、风险解释和服务进度沟通。

AI增长操作系统解决的是顾问被释放后如何参与客户经营的问题：

- 哪些客户值得重点经营；
- 哪些客户存在涨价、续费、增值服务、转介绍机会；
- 顾问应该优先联系谁；
- 应该用什么理由切入；
- 这些判断能否沉淀为下一次可复用的企业规则。

这条线的使用者仍然以顾问为主，同时服务销售、主管和老板。它是 AI 顾问能力的增长升级方向。

## 3. 资料来源与推导结论

### 3.1 亿企赢/客户洞察资料

已有资料中看到的能力与现象：

1. 客户可以从亿企赢导出客户标签数据；
2. 客户基于导出的标签数据，自行让开发做了结果展示功能；
3. 自研展示结果中包含推荐产品、综合得分、六维度评分、匹配依据、建议售卖方式、参考价格、备选产品、上下游关系和网络投放识别；
4. 相关规则支持阈值、权重、关键词、排除词配置；
5. 客户使用标签后，会继续加工成推荐结果、评分、售卖建议和跟进动作。

推导结论：

> 标签数据是基础价值，客户实际使用时需要把标签进一步加工成“推荐方向 + 匹配评分 + 命中依据 + 售卖建议 + 跟进动作”。

对 AI增长操作系统的启发：

- 需要字段标签；
- 需要规则配置；
- 需要评分/排序；
- 需要命中解释；
- 需要可跟进的行动建议；
- 需要反馈后继续优化规则。

---

### 3.2 探迹资料与案例

探迹值得参考的是增长闭环方法。

我们看到的能力包括：

1. 基于企业数据和行业信号筛选目标客户；
2. 通过规则/模型判断客户意向和优先级；
3. 给销售提供触达动作，例如电话、微信、邮件、广告和CRM跟进；
4. 记录销售动作和客户反馈；
5. 用成交、失败、意向等结果反向优化筛选和跟进策略。

四个案例给出的启发：

- 联贝案例说明：同样的销售动作量，如果前面有更准的客户筛选和推荐理由，动作命中率会提升；
- 易账无忧案例说明：增长不只来自新客户，也来自把已有客户关系延伸到更高客单价服务；
- 睿成案例说明：AI工具要和销售SOP、动作量管理、CRM过程记录结合；
- 华运昌案例说明：增长机会可以来自行业客群重构和业务策略配置。

推导结论：

> AI增长操作系统要学习探迹的“数据 + 规则 + 动作 + 记录 + 反馈”循环，但增长场景落在云帐房更有优势的存量客户经营和顾问工作流里。

### 3.3 天工系统资料

《天工系统优势说明》提供了以下能力线索：

1. 六大类商机规则：代账、工商、税筹、知产、资质、法务；
2. 8大类88种企业数据维度；
3. 存量客户关系图谱和转介绍线索；
4. 五大业务健康度指标；
5. 商机成交SOP；
6. 金四风险洞察和报告。

推导结论：

> 天工已经沉淀了一批规则、数据维度、关系图谱、健康度和SOP资产，这些内容可以作为 AI增长操作系统的规则模板、字段来源和业务经验输入。

天工实际销售不理想给出的反向启发：

- 通用规则分析出的商机不一定匹配每家代账公司当前能做的业务；
- 固定规则和固定取数扩展性弱；
- 只做后台闭环，顾问和主管不一定执行；
- 没有进入云微/企微主工作流时，商机很容易停留在系统里。

设计要求：

> AI增长操作系统要把规则、数据和SOP变成顾问可直接使用的规则配置、批量分析和行动建议能力，并允许机构根据自己的业务创建和保存内部规则。

## 4. 产品目标

AI增长操作系统第一阶段要达成三个目标。

### 4.1 让数据可用

把客户、发票、财务、税务、服务、沟通等数据整理成可筛选、可打标签、可解释、可参与规则分析的字段资产。

### 4.2 让规则可创建

让用户基于字段标签和规则引擎创建自己的洞察模板。AI规则助手直接生成结构化规则配置表，用户可以手动修改，然后用少量企业样本验证，最后保存为企业内部规则。

### 4.3 让行动发生

系统每天向顾问推送行动建议清单。

行动建议要足够轻：

- 今天建议联系哪几个客户；
- 为什么联系；
- 推荐说什么；
- 联系后用几个按钮记录结果；
- 系统根据反馈继续优化规则。

## 5. 核心设计原则

### 原则一：从数据标签和规则引擎开始

第一阶段重点是把字段、标签、规则模板和批量分析能力跑通。

优先做：

- 字段字典；
- 标签规则；
- 关键词词库；
- 规则条件组；
- 洞察模板；
- 批量分析；
- 命中解释；
- 推荐名单。

AI 在第一阶段的核心输出不是一段文本建议，而是结构化规则配置表。

---

### 原则二：AI规则助手输出可编辑规则配置表

AI规则助手的标准工作流：

```text
用户自然语言输入目标
  -> AI识别目标场景
  -> AI选择可用字段和标签
  -> AI生成规则配置表
  -> 用户手动修改规则
  -> 小样本企业数据即时验证
  -> 用户确认保存为企业内部规则
  -> 后续批量分析和行动建议使用该规则
```

用户输入示例：

```text
帮我找适合做高新申报的客户
帮我找服务成本高但收费低的客户
帮我找近期可能有工商变更需求的客户
帮我找近半年广告投放比较多的客户
```

AI生成的规则配置表应包含：

| 配置项 | 说明 |
|---|---|
| 规则名称 | 例如“高新申报潜力客户” |
| 适用场景 | 高新申报、涨价、工商、合规、营销等 |
| 客户范围 | 全部客户、指定行业、指定顾问客户、指定区域等 |
| 必须满足条件 | 例如行业=科技/软件/制造，注册年限>=1年 |
| 任一满足条件 | 例如经营范围含技术开发，或存在研发费用，或有知识产权 |
| 排除条件 | 例如已成交该服务、注销客户、同行客户、低风险客户 |
| 关键词 | 技术开发、软件开发、研发、广告投放等 |
| 排除词 | 不适合纳入的关键词 |
| 阈值 | 金额、人次、数量、时间周期等阈值 |
| 权重 | 各条件对评分的影响 |
| 输出字段 | 企业名称、命中原因、关键金额、最近命中时间、推荐等级 |
| 命中解释模板 | 用于向顾问解释为什么命中 |
| 建议动作 | 联系客户、发送资料、转销售、暂缓跟进等 |
| 建议话术 | 供顾问修改后发送 |
| 规则归属 | 系统通用规则 / 企业内部规则 / 个人草稿 |
| 规则状态 | 草稿、验证中、已启用、停用 |

用户可修改内容：

- 字段；
- 操作符；
- 阈值；
- 关键词；
- 排除词；
- 权重；
- 输出字段；
- 命中解释；
- 建议动作；
- 规则名称和归属。

---

### 原则三：少量企业数据验证后再保存规则

规则生成后先用少量企业样本验证，而不是直接全量运行。

验证方式：

1. 用户选择样本范围，例如 20-50 家企业；
2. 系统展示命中客户和未命中客户；
3. AI解释每个客户为什么命中；
4. 用户标记：准确、不准确、需要调整；
5. 用户根据样本反馈修改阈值、关键词、排除词和权重；
6. 用户确认后保存为企业内部规则。

样本验证页需要展示：

- 命中企业列表；
- 未命中但接近命中的企业；
- 命中字段；
- 命中关键词；
- 命中金额/次数；
- AI分析说明；
- 用户反馈按钮；
- 规则调整入口。

保存后的规则进入：

- 企业内部规则库；
- 个人草稿规则；
- 候选通用规则池。

---

### 原则四：先做规则清单，不做重型产品资产中心

第一阶段实现为“规则清单/模板清单”：

- 模板名称；
- 推荐方向；
- 适用客户；
- 命中字段；
- 命中解释；
- 推荐动作；
- 推荐话术；
- 是否通用模板；
- 是否机构私有模板。

当某类规则持续产生有效反馈后，再逐步沉淀成更正式的可售产品体系。

---

### 原则五：用行动建议清单降低流程监管阻力

强流程监管容易增加顾问抵触。第一阶段采用“每日行动建议清单 + 轻量反馈”。

每日清单内容：

- 推荐联系客户；
- 推荐原因；
- 推荐动作；
- AI话术；
- 一键标记结果。

轻量反馈选项：

```text
已联系 - 有兴趣
已联系 - 暂无需求
未联系 - 稍后提醒
不适合 - 原因选择
转销售跟进
```

主管和老板看到汇总结果：

- 哪些建议被采纳；
- 哪些客户有兴趣；
- 哪些规则效果好；
- 哪些顾问反馈积极；
- 哪些模板需要优化。

---

### 原则六：云微聊天记录是重要数据源

云微/企微聊天记录不只是执行入口，也可以作为数据分析输入。

需要分析：

- 顾问和客户真实聊什么；
- 是否出现工商、税筹、融资、社保、开票、广告、高新、资质、合规等商机关键词；
- 客户是否主动表达需求；
- 顾问是否已经在聊天中做过推荐；
- 客户是否有异议或拒绝理由；
- 哪些问题高频出现，可以转成规则或模板。

## 6. 数据分层设计

### 6.1 原始数据层

包括：

- 企业基础信息：名称、税号、行业、地址、成立时间、经营范围；
- 工商数据：法人、股东、变更、关联企业、经营状态；
- 发票数据：发票项目、金额、日期、关键词、供应商；
- 财务数据：收入、利润、研发费用、暂估、库存、往来；
- 税务数据：纳税人类型、纳税信用、税额、税负率、零申报、小规模开票额；
- 服务数据：服务时长、当前价格、凭证数、流水数、咨询次数、模块使用情况；
- 沟通数据：群消息、客户问题、顾问回复、关键词、客户意图；
- 外部数据：风险、资质、知识产权、政策补贴、经营异常。

### 6.2 标签与衍生字段层

原始字段沉淀为标签和衍生字段：

- 高营收客户；
- 高票量客户；
- 低价高耗客户；
- 广告投放客户；
- 高新潜客；
- 工商变更意图；
- 社保增减员意图；
- 合规风险客户；
- 转介绍关系客户。

### 6.3 规则配置层

基于标签和字段配置规则：

- 系统预置规则；
- AI生成规则草稿；
- 用户手动修改规则；
- 企业内部规则；
- 候选通用规则。

### 6.4 小样本验证层

规则保存前先用少量企业样本测试：

- 命中企业；
- 未命中企业；
- 接近命中企业；
- 用户反馈；
- 规则调整记录。

### 6.5 分析结果层

输出：

- 推荐客户名单；
- 命中原因；
- 关键证据；
- 推荐等级；
- AI分析说明；
- 建议动作；
- 建议话术。

### 6.6 行动与反馈层

输出到顾问工作流：

- 今日行动建议；
- 云微侧边栏提醒；
- AI话术；
- 一键反馈；
- 结果沉淀；
- 规则效果统计。

## 7. 产品形态

### 7.1 规则模板中心

用户可以查看和创建模板：

- 系统推荐模板；
- 企业内部模板；
- AI生成模板草稿；
- 已验证高转化模板；

### 7.2 AI规则助手

页面结构：

1. 自然语言输入框；

### 7.3 批量分析任务

用户选择已保存规则后批量分析客户：

- 选择规则模板；
- 执行分析；
- 生成客户名单；
- 查看AI分析结果；
- 导出或推送给顾问。

### 7.4 顾问行动建议清单

每天推送：

- 今日建议联系客户；

- 建议话术；
- 快捷反馈；
- 稍后提醒；
- 转销售/主管。

入口：

- 云微侧边栏；
- 顾问工作台；
- 每日摘要消息；
- 主管分配任务。

### 7.5 规则效果看板

看规则效果：

- 规则命中数；
- 顾问采纳数；
- 有兴趣客户数；
- 转销售数；
- 成交数；
- 失败原因；
- 建议优化方向。

## 8. MVP怎么做

MVP采用“两条腿走路”。

### 8.1 系统预置模板

先提供几个可理解、容易验证、数据可取的模板，例如：

1. 可涨价代账客户；
2. 广告/数字营销商机客户；
3. 高新申报潜力客户；
4. 合规体检客户；
5. 工商变更客户；
6. 小规模开票风险客户；
7. 社保/人资服务客户；
8. 融资/贷款潜力客户。

第一批模板由数据可得性和客户现场需求共同决定。

### 8.2 AI现场生成企业内部规则

到客户现场展示时，可以让客户提出自己的问题：

```text
你们现在最想找什么客户？
你们现在最想卖什么服务？
你们觉得哪些客户最有价值？
```

AI基于字段字典和已有模板生成规则配置表。用户手动修改后，用少量企业数据验证，确认可用后保存成企业内部规则。

这样可以沉淀两类资产：

- 通用模板：多家客户都认可，可以产品化；
- 企业内部规则：某家机构独有，作为机构配置能力。

## 9. 阶段规划、支撑与周期预估

### 阶段1：数据与规则盘点（1-2周）

目标：确认数据能不能支撑第一批规则。

工作内容：

1. 梳理P0字段字典；
2. 梳理标签和衍生字段；
3. 梳理已有规则表和天工规则资产；
4. 分析云微聊天记录，提取真实商机沟通关键词和客户意图；
5. 访谈顾问/销售，确认真实可售服务和常见客户问题；
6. 形成第一批候选模板。

需要支撑：

- 数据侧：提供财云、发票、税务、服务、云微聊天记录样本；
- 产品侧：整理字段口径和模板规则；
- 业务侧：提供可售服务方向和顾问真实场景；
- 技术侧：评估云微聊天记录可读取范围和脱敏方式。

产出：

- P0字段字典；
- 聊天记录商机关键词分析；
- 候选规则模板清单；
- 数据缺口清单；
- 第一批离线分析方案。

---

### 阶段2：离线规则验证（2周）

目标：验证规则能否跑出有价值的客户名单。

工作内容：

1. 使用SQL/脚本/表格跑批量名单；
2. 输出命中原因和AI分析说明；
3. 与顾问/销售/老板一起评审名单；
4. 标记名单质量：值得跟进、不适合、规则需调整；
5. 记录客户现场提出的新规则需求。

需要支撑：

- 数据侧：离线跑数；
- 产品侧：准备名单样例和解释口径；
- 业务侧：组织顾问/销售评审；
- AI侧：生成命中解释和跟进建议。

产出：

- 第一批客户名单；
- 名单质量反馈；
- 调整后的规则模板；
- 通用规则/私有规则初步分类。

---

### 阶段3：AI规则助手与规则配置表原型（3-4周）

目标：让用户能通过AI生成规则配置表，并手动修改、验证、保存为企业内部规则。

工作内容：

1. 自然语言输入目标客户；
2. AI生成结构化规则配置表；
3. 用户修改字段、条件、关键词、排除词、阈值和权重；
4. 小样本企业数据验证；
5. 命中解释生成；
6. 用户确认保存企业内部规则；
7. 已保存规则用于批量分析和名单导出。

需要支撑：

- 研发侧：规则配置表、条件组、小样本验证原型；
- AI侧：自然语言转结构化规则配置表；
- 产品侧：规则配置交互和样本验证交互；
- 数据侧：字段接口、样本查询和权限控制。

产出：

- AI规则助手；
- 规则配置表编辑页；
- 小样本验证页；
- 企业内部规则保存能力；
- 批量分析原型；
- 推荐名单页。

---

### 阶段4：云微行动建议清单（3-4周）

目标：让分析结果进入顾问日常工作流。

工作内容：

1. 云微侧边栏展示客户机会；
2. 每日行动建议清单；
3. AI话术生成；
4. 顾问一键反馈；
5. 稍后提醒/转销售/不适合原因；
6. 反馈回流规则效果看板。

需要支撑：

- 云微/企微侧：入口、侧边栏、消息推送；
- AI侧：话术生成和聊天上下文摘要；
- 产品侧：轻量反馈交互；
- 业务侧：定义顾问反馈选项。

产出：

- 云微侧边栏机会提示；
- 每日建议行动清单；
- 顾问反馈数据；
- 规则效果看板。

---

### 阶段5：规则沉淀与规模化（持续迭代）

目标：把正反馈规则变成可复用资产。

工作内容：

1. 分析哪些模板被使用最多；
2. 分析哪些规则带来有效反馈；
3. 把多家机构都认可的规则沉淀为通用模板；
4. 把单家机构规则保留为企业内部规则；
5. 支持模板复制、调整和行业化。

需要支撑：

- 数据侧：规则效果统计；
- 产品侧：模板版本管理；
- 业务侧：提炼通用增长场景；
- AI侧：规则优化建议。

产出：

- 通用模板库；
- 企业内部规则库；
- 规则效果排行榜；
- 行业/区域模板包。

## 11. 风险与应对

| 风险 | 说明 | 应对 |
|---|---|---|
| 字段口径不清 | 数据无法支撑规则稳定运行 | 阶段1先做字段字典和口径确认 |
| 规则过宽 | 名单多但价值低 | 小样本验证，加入排除词、阈值和人工反馈 |
| 用户不会创建规则 | 规则引擎门槛高 | AI直接生成规则配置表，用户只做修改和确认 |
| 顾问不愿反馈 | 流程监管反人性 | 用每日行动建议 + 轻量按钮反馈替代重CRM |
| 只沉淀私有规则 | 通用化不足 | 持续识别多家客户都适用的规则，沉淀为通用模板 |
| 云微接入慢 | 行动闭环延后 | 先离线名单验证，再接云微行动建议清单 |

## 12. 汇报建议话术

可以这样讲：

> 我们建议把增长方向设计成 AI增长操作系统。它的起点是字段标签和规则引擎，但核心体验不是让用户自己复杂配置，而是让AI直接生成结构化规则配置表。用户可以修改字段、阈值、关键词、排除词和权重，然后用少量企业样本验证，确认后保存为企业内部规则。保存后的规则可以批量分析客户，输出推荐名单和AI分析结果，再通过云微每天推送顾问行动建议清单，用轻量反馈收集正反馈。后续我们把多家客户都验证有效的规则沉淀为通用模板，把单家客户自己的规则沉淀为企业内部规则，形成持续迭代的增长系统。

## 13. 最终建议

明天汇报建议聚焦三个结论：

1. **产品方向**：AI增长操作系统从“数据标签 + 规则引擎 + AI生成规则配置表”开始，不先做重型CRM或大而全商机平台。
2. **验证方式**：规则先由AI生成配置表，用户手动修改，再用少量企业数据验证，最后保存为企业内部规则。
3. **行动闭环**：用每日行动建议清单和轻量反馈替代强流程监管，逐步沉淀通用模板和企业内部规则。

近期最重要的产出是：

> P0字段字典 + 聊天记录商机分析 + 第一批候选规则模板 + 离线名单验证 + AI规则助手原型。
