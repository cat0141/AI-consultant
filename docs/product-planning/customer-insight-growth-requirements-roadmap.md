## 1. 结论先行

如果只考虑“商机洞察 / 增长获客”，该产品不应被定义为AI服务顾问的一期提效模块，而应作为一条独立的客户洞察增长线推进。

建议产品定位为：

> 客户洞察增长平台：基于代账机构已有客户的工商、票财税、服务、沟通、标签和历史交易数据，自动识别可涨价、可续费、可推荐增值服务的客户名单，并给出推荐产品、命中依据、跟进建议和转化管理能力。

核心判断：

1. 该产品的核心目标是 **增收**，不是提效；
2. 用户真正要的不是“看报表”，而是“拿到可跟进、可转化、可复盘的客户名单”；
3. 第一阶段不应先做复杂AI，而应先做字段字典、洞察模板、规则引擎、名单输出和命中解释；
4. 商业价值成立的前提是：名单足够准、销售愿意跟、老板能看到收入提升；
5. MVP应优先用 3 个模板验证：可涨价代账客户、广告/数字营销商机、高新申报潜力客户。

## 2. 信息来源与推导结论

### 2.1 信息来源一：竞品客户洞察截图

已获取信息：

- 竞品/客户洞察类产品入口包含客户一览表、商机速览、洞察模板、洞察报表、设置；
- 页面表达为“客户洞察—盘户增值 助力转化”；
- 核心能力包括聚合客户信息、促进转介绍营销、获得商业机会；
- 系统强调 200+ 筛选维度、灵活组合查找、识别优质客户。

推导结论：

> 商机洞察类产品不应只是数据表，而应是围绕“盘户增值、客户经营、商机转化”的业务入口。

需求建议：

- 产品首页要体现商机数量、商机金额、跟进状态和转化效果；
- 不应只提供空白筛选器，应内置洞察模板；
- 客户数据聚合、关系网络、商机识别应放在同一产品叙事中。

### 2.2 信息来源二：竞品/客户洞察模板规则筛选器截图

已获取信息：

- 支持“满足以下所有条件”；
- 支持嵌套“满足以下任一条件”；
- 支持数值区间、包含、不包含、枚举标签等操作；
- 字段覆盖代账服务状态、服务时长、近12个月累计收入、代账单价变化、凭证数、销项发票数量、流水条数、微信服务咨询对话数、功能使用状态等；
- 支持“使用模板”。

推导结论：

> 规则引擎是商机洞察产品的底层核心，不是辅助能力。模板化是降低使用门槛的关键。

需求建议：

- 必须支持条件组：全部满足、满足任一、全部满足 + 任一组；
- 必须支持跨域字段组合：客户、票据、财务、税务、服务、互动、产品使用状态；
- 必须支持模板保存、复用、复制和调整；
- 第一版可以先不做复杂AI，但必须先把规则引擎做扎实。

- 月均发票量；
- 银行账户数量；

发票维度包括：

推导结论：

> 已经具备第一批字段池和第一个明确商机模板，即“广告/数字营销服务商机”。

需求建议：

- 建立字段字典；
- 建立广告/数字营销关键词词库；
- 输出企业明细时必须包含命中关键词、命中金额、命中次数、最近命中时间；

已获取信息：

客户基于亿企赢导出的客户标签数据，自行让开发设计了结果展示功能，截图中包括：

- 推荐产品：如高新认证、垫资验资、公司法人变更；
- 综合得分；
- 六维度评分：行业匹配、注册年限、地区匹配、企业规模、经营范围、往来科目；
- 匹配依据；
- 建议售卖方式；
- 参考价格；
- 备选产品；
- 上下游关系与网络投放识别；
- 规则阈值、权重、关键词、排除词配置。

推导结论：

> 客户并不满足于“导出标签数据”，而是希望把标签数据转化为“产品机会评分 + 推荐结果展示 + 售卖建议”。

需求建议：

- 结果页不能只是名单表，必须提供推荐卡片；
- 每个客户应展示推荐产品、匹配度、推荐等级、命中依据、建议售卖方式、参考价格；
- 产品机会评分模型应成为核心能力；
- 规则需要支持阈值、权重、关键词、排除词配置；
- 后续应支持备选产品推荐。

已获取信息：

- 表中包含量化洞察方案、画像字段清单、使用说明；

- 覆盖客户规模洞察、行业专项洞察、数智产品交付洞察、代账业务增长洞察、财税合规风险洞察、基础合规分层、合规管家商机、开票风险、高新申报、金融需求等；
- 每条规则包含洞察方案、客户标签/分层、命中方式、量化判断口径、输出名单、运营动作、优先级；
- 画像字段覆盖业务信息和服务档案。

推导结论：

> 客户已经将“客户洞察”拆成了可运营的规则体系。真正的产品形态应是“洞察模板运营规则引擎”。

需求建议：

- 每个洞察模板必须明确输出什么名单；
- 每个名单必须对应运营动作；
- 每条规则必须能配置优先级；
- 应优先选择已具备明确业务动作和商业价值的模板；
- 表格可作为第一版模板规则配置的原型。

### 2.6 信息来源六：2026-06-09 AI顾问产品讨论会

已获取信息：

- 会议中将AI服务顾问效率线与客户洞察增长线进行了区分；
- 一线反馈认为商机洞察、合规报告、客户分层、增值业务推荐更偏增长和营收提升；
- 会议中也指出报告本身价值有限，关键是报告能不能帮助客户卖出去或形成实际业务动作；
- 商机洞察可作为并行或二期模块，不宜牵引AI服务顾问一期提效主线。

推导结论：

> 商机洞察增长线具备独立产品价值，但不应与AI服务顾问一期混在一起。其成功标准不是“是否智能”，而是“是否带来可跟进商机和可验证收入”。

需求建议：

- 作为独立增长产品线推进；
- 以客户名单、产品推荐、跟进闭环、成交复盘作为主线；
- 避免只做漂亮报告或空泛AI分析。

## 3. 用户需求总结

从以上资料可以归纳出 6 类核心需求。

### 3.1 客户分层需求

用户希望将大量存量客户按价值、行业、规模、风险、活跃度、服务复杂度进行分层。

典型诉求：

- 哪些是高价值客户；
- 哪些是低价高耗客户；
- 哪些是成长型客户；
- 哪些是高风险客户；
- 哪些客户适合重点运营。

### 3.2 商机识别需求

用户希望从已有客户数据中发现增值业务机会。

典型商机：

- 可涨价客户；
- 广告/数字营销服务商机；
- 高新申报潜力客户；
- 小规模开票风险预警；
- 合规体检目标客户；
- 贷款/融资潜力客户；
- 工商变更/资质办理客户；
- 续费、转介绍、复购客户。

### 3.3 产品推荐需求

用户不是只想知道客户有什么标签，而是想知道：

- 该客户适合推什么产品；
- 为什么适合推；
- 匹配度多少；
- 预计价值多少；
- 有无备选产品；
- 应该怎么切入。

### 3.4 可解释需求

商机推荐必须能解释，否则一线不会信。

需要展示：

- 命中字段；
- 命中关键词；
- 命中金额；
- 命中次数；
- 最近一次命中时间；
- 维度得分；
- 推荐原因。

### 3.5 运营跟进需求

商机名单必须能进入后续运营动作。

需要支持：

- 分派；
- 跟进状态；
- 跟进记录；
- 下次提醒；
- 预计金额；
- 成交金额；
- 失败原因；
- 转化复盘。

### 3.6 自定义配置需求

不同代账公司有不同增值产品和销售能力，不能只提供固定规则。

需要支持：

- 机构自定义产品；
- 自定义关键词；
- 自定义排除词；
- 自定义评分权重；
- 自定义推荐阈值；
- 自定义输出字段；
- 自定义模板保存和复用。

## 4. 产品设计建议

### 4.1 产品名称与定位

建议产品名：

> 客户洞察增长平台

一句话定位：

> 帮代账机构从已有客户中发现可转化、可涨价、可续费、可推荐增值服务的客户名单，并提供推荐产品、命中依据、运营动作和转化跟踪。

### 4.2 产品全链路

完整链路如下：

```text
数据接入
  -> 字段清洗与客户画像
  -> 标签体系
  -> 洞察模板/规则引擎
  -> 商机识别
  -> 产品机会评分
  -> 推荐名单输出
  -> 命中原因解释
  -> 运营动作/话术生成
  -> 分派跟进
  -> 转化结果回收
  -> 规则优化
```

### 4.3 核心模块

| 模块 | 说明 | 优先级 |
|---|---|---|
| 字段字典 | 明确字段来源、口径、类型、权限、是否可筛选/评分/导出 | P0 |
| 关键词词库 | 按商机场景维护关键词和排除词 | P0 |
| 标签体系 | 将字段和规则转化为客户标签 | P0 |
| 洞察模板库 | 内置可涨价、高新、广告营销等模板 | P0 |
| 规则引擎 | 支持全部满足、满足任一、嵌套条件组 | P0 |
| 名单输出 | 输出可跟进客户池 | P0 |
| 命中解释 | 展示命中字段、关键词、金额、次数和原因 | P0 |
| 导出能力 | 支持Excel/CSV导出 | P0 |
| 产品机会评分 | 对客户与推荐产品计算匹配度 | P1 |
| 推荐卡片 | 展示推荐产品、分数、原因、话术、参考价格 | P1 |
| 跟进闭环 | 分派、状态、记录、成交、失败原因 | P1/P2 |
| AI增强 | AI生成规则、解释、话术、复盘 | P2 |

## 5. 第一批MVP模板建议

第一版不建议做太多模板，应选 3 个高价值、规则明确、容易验证的模板。

### 5.1 可涨价代账客户

价值：直接提升代账服务收入，老板感知最强。

典型规则：

```text
代账服务状态 != 已流失
AND 代账服务时长 >= 365天
AND 近12个月累计收入达到阈值
AND 当前代账单价 < 机构平均单价
AND (
  凭证数较高
  OR 销项发票数量较高
  OR 流水条数较高
  OR 咨询对话数量较高
  OR 使用库存/资产/辅助核算等复杂功能
)
```

输出：涨价沟通名单。

运营动作：客户经理联系客户，说明服务复杂度、工作量增加和价格偏低，推进调价。

### 5.2 广告/数字营销商机客户

价值：识别已有营销投入的客户，可推荐新媒体推广、广告投放优化、SEO/SEM/GEO等服务。

典型规则：

```text
发票项目包含以下任一关键词：
网络投放、广告投放、数字营销、信息流、搜索引擎推广、媒体投放、SEO、SEM、营销推广、品牌推广

OR

供应商名称 / 应付账款 / 往来科目包含：
广告、传媒、网络科技、推广服务、营销策划
```

输出：广告/数字营销服务商机名单。

运营动作：从已有同类采购习惯、效果优化、成本控制、服务质量对比切入。

### 5.3 高新申报潜力客户

价值：高客单价资质服务机会。

典型规则：

```text
行业属于科技、软件、信息技术、科研、制造、环保、电子设备等
AND 注册年限满足要求
AND 经营范围包含技术开发、技术服务、软件开发、研发、技术咨询、科技
AND 存在研发费用 / 技术服务相关发票 / 知识产权相关线索
```

输出：高新申报潜客名单。

运营动作：推荐高新认定、研发费用归集、知识产权、项目申报服务。

## 6. 阶段规划

### 6.1 阶段0：规则和数据盘点

目标：先判断能不能做、哪些数据能拿到、哪些规则有价值。

要做的事：

1. 梳理现有数据字段；
2. 确认字段口径；
3. 梳理客户已有规则表；
4. 挑选第一批模板；
5. 确认每个模板的输出名单；
6. 确认每个名单的运营动作；
7. 确认客户是否愿意拿这些名单跟进。

产出物：

```text
字段字典
规则模板清单
第一批MVP模板
输出字段清单
运营动作清单
数据缺口清单
```

判断标准：

```text
筛谁？
为什么筛？
推什么？
谁跟进？
怎么判断有效？
```

如果一个模板不能回答这五个问题，先不进入MVP。

### 6.2 阶段1：规则引擎与名单输出

目标：不急着做复杂AI，先把可用名单跑出来。

优先实现：

- 字段选择；
- 条件配置；
- 关键词匹配；
- 条件组：全部满足 / 任一满足；
- 名单生成；
- 命中原因展示；
- Excel/CSV导出。

结果形式：

```text
客户名单
推荐产品
命中字段
命中关键词
命中金额/次数
推荐等级
导出文件
```

阶段验证重点：

- 名单准不准；
- 销售愿不愿意跟；
- 客户经理能不能理解命中原因；
- 老板是否觉得名单有商业价值。

### 6.3 阶段2：产品机会评分与推荐卡片

目标：从“筛出客户”升级为“告诉用户优先跟谁、推什么、为什么”。

要做的事：

1. 为每个模板配置评分维度；
2. 设置权重；
3. 设置推荐阈值；
4. 设置高/中/低优先级；
5. 展示推荐卡片；
6. 支持备选产品；
7. 支持参考价格；
8. 支持建议售卖方式。

页面重点：

```text
商机速览页
客户推荐卡片页
商机明细列表页
```

### 6.4 阶段3：跟进闭环

目标：让商机真正转化，不只是看名单。

要做的事：

1. 商机分派；
2. 跟进状态；
3. 跟进记录；
4. 下次提醒；
5. 转化结果；
6. 失败原因；
7. 模板效果统计。

关键指标：

```text
生成商机数
高优先级商机数
跟进率
意向率
成交率
成交金额
模板转化率
顾问跟进效率
```

### 6.5 阶段4：AI增强

目标：让AI做辅助，而不是让AI一开始承担全部判断。

适合AI介入的位置：

1. **AI生成规则**：用户输入“帮我找最近可能需要做高新申报的客户”，AI生成可编辑规则；
2. **AI解释命中原因**：将结构化规则转成自然语言；
3. **AI生成跟进话术**：根据推荐产品和命中原因生成沟通话术；
4. **AI总结复盘**：分析哪个模板、关键词、行业、顾问转化效果更好。

原则：

> AI是增强层，不是底层。底层必须是字段、规则、模板、评分和跟进数据。

## 7. 商业价值评估

### 7.1 价值成立点

该产品具备商业价值，原因包括：

1. **直接对应代账机构收入增长**  
   可涨价客户、高新申报、广告营销、合规体检、融资服务都可形成收入机会。

2. **客户已有真实行为**  
   客户已经在导出亿企赢标签数据，并自行让开发做分析结果展示，说明需求不是想象出来的。

3. **可用现有数据先跑MVP**  
   不需要一开始建设完整AI系统，先用字段和规则就能验证名单价值。

4. **老板容易感知价值**  
   商机数、跟进率、成交金额、涨价金额都可量化。

5. **可形成持续运营能力**  
   一旦模板转化有效，可以不断扩展新产品、新规则、新行业和新客户池。

### 7.2 商业化模式建议

可考虑以下模式：

| 模式 | 说明 | 适用阶段 |
|---|---|---|
| 增值模块收费 | 作为客户洞察/增长模块单独收费 | MVP后 |
| 按客户数/客户包收费 | 代账客户数越多，价值越明显 | 商业化阶段 |
| 按模板包收费 | 高新、合规、涨价、营销、融资等模板包 | 商业化阶段 |
| 按成交/效果分成 | 与部分增值服务合作时可考虑 | 后期 |
| 打包进高阶版本 | 作为企业版/高级版能力 | 商业化阶段 |

### 7.3 商业价值验证指标

MVP阶段重点验证：

| 指标 | 说明 |
|---|---|
| 名单命中准确率 | 一线认为名单是否值得跟 |
| 名单跟进率 | 客户经理是否愿意跟进 |
| 有意向率 | 跟进后客户是否有兴趣 |
| 成交率 | 是否真实转化 |
| 成交金额/涨价金额 | 是否产生收入 |
| 单模板贡献金额 | 哪些模板最有价值 |
| 客户愿付费比例 | 是否愿意为该模块付费 |

## 8. 风险与应对

| 风险 | 说明 | 应对 |
|---|---|---|
| 数据口径不清 | 收入、发票金额、研发费用等字段容易有口径争议 | 先做字段字典和口径确认 |
| 名单误判高 | 规则过宽会导致无效名单多 | 加推荐阈值、排除词、命中解释和人工复核 |
| 一线不跟进 | 只生成名单但没有运营动作 | 每个模板必须绑定运营动作和负责人 |
| 只看报表不转化 | 报表价值弱，难以商业化 | 重点做名单、分派、跟进、成交复盘 |
| 模板过多导致失焦 | 一期做太多规则，难验证 | 先做3个MVP模板 |
| AI效果不稳定 | AI直接判断商机可能不可控 | 先规则后AI，AI只做解释和辅助配置 |
| 客户产品承接能力不同 | 不同机构能卖的服务不同 | 支持机构自定义产品和模板 |

## 9. 下一步要做什么

## 10. 最终建议

该产品线建议按以下原则推进：

> 先不要做复杂AI，不要先做大而全CRM，也不要先做漂亮报告。先用明确字段 + 洞察模板 + 规则引擎，跑出可解释、可导出、可跟进的高价值客户名单。

推荐落地顺序：

```text
字段字典
-> 模板规则
-> 离线名单验证
-> 名单页/导出
-> 推荐评分
-> 跟进闭环
-> AI话术/AI规则生成
```

短期成功标准：

> 三个MVP模板能够稳定跑出名单，并且一线愿意跟进，客户能产生真实意向或成交。

如果该标准成立，客户洞察增长平台具备明确商业化价值，可作为独立增值模块或高阶版本能力推进。
